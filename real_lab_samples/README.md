# Enterprise-Schema Lab Telemetry Samples (`real_lab_samples/`)

While the primary `.zip` archives in the root folders use a simplified flat key-value format (`attack="SIMULATED_*"`) for fast beginner `grep` / `awk` exercises, this directory provides **un-flattened, enterprise-schema JSON samples** modeled on the exact field hierarchies generated by our Wazuh + Windows 11 + Rocky Linux 9 home lab (`192.168.198.0/24`).

Each file is curated and sanitized to include both **benign baseline activity** and a **multi-step attack sequence** so you can test SIEM parsers, Wazuh decoders/rules, and correlation thresholds without standing up the full 4-VM lab.

---

## Sample Telemetry Files

### 1. `windows_sysmon_process_creation.json` (5 Events)
* **Schema:** Wazuh Windows EventChannel wrapper (`win.system.*` + `win.eventdata.*`) around Microsoft Sysmon (`Microsoft-Windows-Sysmon/Operational`, Event ID `1`).
* **Included Activity:**
  * **Benign Baseline (2 events):** `services.exe` -> `svchost.exe -k netsvcs -p` (PID `1420`) and `MsMpEng.exe` -> `MpCmdRun.exe -Scan -ScanType 1` (PID `4116`).
  * **Attack Chain (3 events — `T1059.003`, `T1059.001`, `T1033`):** `explorer.exe` (PID `2940`) -> `cmd.exe /c start /b powershell.exe ...` (PID `3104`) -> `powershell.exe -NoP -NonI -W Hidden -enc ...` (PID `4892`, encoded `Net.WebClient` download cradle targeting `http://192.168.198.128:8080/payload`) -> `whoami.exe /priv` (PID `5108`).
* **Lineage Integrity:** Every `parentProcessGuid` links directly to the parent event's `processGuid`, sharing the host's 32-bit Sysmon machine prefix (`748f2c1a`).

### 2. `windows_security_logon_4625.json` (8 Events)
* **Schema:** Wazuh Windows EventChannel wrapper around Windows Security Auditing (`Security`, Event IDs `4625` & `4624`).
* **Included Activity:**
  * **Benign Baseline (1 event):** Local interactive logon (`EventID: 4624`, `logonType: "2"`) for domain user `CORP\m.jaber`.
  * **RDP Brute-Force Burst (6 events — `T1110.001`):** 6 rapid NTLM/RDP authentication failures (`EventID: 4625`, `logonType: "10"`, `status: "0xc000006d"`) from Kali (`192.168.198.128`, ports `53180`–`53194`), covering both invalid-account (`subStatus: "0xc0000064"` on `admin`) and bad-password (`subStatus: "0xc000006a"` on `Administrator`) failures — enough events to trigger `count > 5` correlation queries.
  * **Post-Brute-Force Compromise (1 event — `T1078`):** Successful RDP logon (`EventID: 4624`, `logonType: "10"`, `lmPackageName: "NTLM V2"`, `keyLength: "128"`) from `192.168.198.128` (`targetLogonId: "0x2f3e4"`).

### 3. `suricata_nids_eve.json` (6 Events)
* **Schema:** Suricata 7 Extensible Event Format (`eve.json`) on interface `ens160` (`192.168.198.128` -> `192.168.198.132`).
* **Included Activity:**
  * **Emerging Threats / GPL Nmap Scan Alerts (3 events — `T1046`):**
    * `signature_id: 2001219` — `ET SCAN Potential SSH Scan` (`TCP :22`)
    * `signature_id: 2100528` — `GPL SCAN nmap TCP` (`TCP :80`, Xmas flags `FIN+PSH+URG`)
    * `signature_id: 2009582` — `ET SCAN Nmap Scripting Engine User-Agent Detected` (`HTTP :80`)
  * **Custom Lab ICMPv6 Test Alert (1 event):**
    * `signature_id: 9000001` — `TEST_ALERT: Ping detected from Kali` (`IPv6-ICMP`), used in our Wazuh lab to test scoped `level="0"` child suppression (`Rule 100060`).
  * **Supporting Non-Alert EVE Records (2 events):** An `event_type: "ssh"` record showing `paramiko_3.4.0` (NetExec SSH spray client banner) and an `event_type: "flow"` record.

> **Important Schema Note (`alert.signature_id` vs. Wazuh `rule.id`):** In Suricata's `eve.json`, `alert.signature_id` holds the **Suricata rule SID** (e.g. `2001219` for Emerging Threats or `9000001` for a local custom rule). When Wazuh ingests `eve.json` via `<log_format>json</log_format>`, Wazuh's `0475-suricata_rules.xml` matches all Suricata alert records under **Wazuh `rule.id: 86601`** while preserving Suricata's SID inside `data.alert.signature_id`.
